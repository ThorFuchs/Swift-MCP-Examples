# Journey and exchange contract

Distinguish research workflow stages from actual SDK exchange records.

## Overview

Five planned stages correspond to Prepare, Search, Outline, Read and
References. Preparation combines discovery and catalogue listing; additional
catalogue pages can increase the number of real SDK exchanges beyond six.

The journey projection accepts only a non-idle journey associated with the
currently selected server run. Repeated observations remain available.
Unobserved stages are not represented as active or completed.

Preparation checks the protocol and catalogue; successful tool stages check
schema and identity. Transport outcome is independent of application
validation. The exchange inspector records up to 32 opt-in entries:
known method, known tool, SDK request body bytes, delivered message bytes,
message count, measured duration and transport outcome.

The exchange order is retained-record order. There are no shared start
timestamps, so an exchange duration chart is not a waterfall. These byte
counts exclude HTTP, TLS and TCP framing. Disabling inspection hides retained
exchange metadata; existing journey/clear lifecycle controls deletion.

Selection is shared by the duration chart, byte chart and native Picker.
No visualization submits a request or captures additional information.
